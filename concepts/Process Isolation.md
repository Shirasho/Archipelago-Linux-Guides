When games are installed on Steam in Linux, Steam places each game in its own Wine prefix. This acts as a sort of security sandbox and disallows games from talking to each other. It also ensures that games with conflicting dependencies do not step on each other. This has the added downside that helper apps may struggle to see the game process. In the context of Archipelago this can mean that the Archipelago client cannot see the game process and therefore cannot attach to it to read/write its memory.

In many cases this can be worked around by installing the second application in the same Wine prefix so they share the exact same file mount, registry, and IPC sockets. This allows us to launch two apps with `proton` (with the same `WINEPREFIX` and `STEAM_COMPAT_DATA_PATH`) and they will be able to talk to each other. For some games this isn't enough. Final Fantasy XII is one such example - even if the Archipelago client is run using the same prefix as the game, the Archipelago client cannot see the game process. For such situations a script such as [Protonhax](https://github.com/jcnils/protonhax) must be used. Protonhax forces an application to be launched within a running Proton instance by launching an application using `Cmd.exe` within that Proton instance.

Guides that require Protonhax should make it known upfront that Protonhax is a requirement if just sharing a prefix is insufficient.
